# 第 2 章：张三复制只读接口

第二天，李四让张三做一个只读的公告接口。

张三想：“这次简单，只要列表和详情。”于是他复制了昨天的 ViewSet，然后把创建、更新、删除几个入口都删掉。

李四说：“只读资源有自己的入口，不用手动裁剪。”

## 张三的低效写法

张三用完整 CRUD 的思路处理只读资源，最后再想办法禁用写操作。

这会带来两个问题：

- 路由意图不清楚
- 以后别人看到完整 ViewSet，会误以为这个资源支持写操作

## 李四的提醒

只读资源应该用 `ReadOnlyModelViewSet`。

它只注册：

```txt
GET /resources
GET /resources/:id
```

## sgin 推荐写法

适合只读 ViewSet 的场景：

- 公告
- 字典
- 分类
- 公开展示资源
- 只允许后台导入、前台读取的数据

如果后续确实要加写操作，再切换到 `ModelViewSet`。

## 这一章记住什么

只读就是只读。不要用完整 CRUD 再靠权限或 handler 去假装只读。
